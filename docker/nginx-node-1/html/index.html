🛡️ Nginx Node 1 - WAF AI Demo

ℹ️ Server Information

  • Node ID: nginx-node-1
  • Purpose: Demonstration web server for WAF AI testing
  • Port: 8081 (external)
  • WAF Status: Protected

🔗 Available API Endpoints

  • GET /api/users - List users
  • GET /api/login - Login endpoint
  • GET /api/search - Search functionality
  • GET /admin/ - Admin panel (restricted)

🔒 Security Features

  • Rate Limiting: 10 requests/second (general), 5 requests/second (API)
  • WAF Rules: AI-generated rules applied dynamically
  • Security Headers: XSS protection, content type options, frame options
  • Admin Protection: Enhanced security for /admin/ paths
  • File Blocking: Sensitive files (.env, .git, etc.) blocked

🧪 Testing Commands

Test this server with various requests. Every command below was run against this node and the status shown is what it actually returns.

# Normal request  -> 200
curl http://localhost:8081/

# API request  -> 200
curl http://localhost:8081/api/users

# SQL injection attempt  -> 403 (blocked)
# The rule matches the words, so the pattern has to be there. Spaces are + .
curl "http://localhost:8081/api/search?q=union+select"

# XSS attempt  -> 403 (blocked)
# Note the path: /api/search . There is no /search route on this node, so using
# it returns a 404 that has nothing to do with the WAF.
curl "http://localhost:8081/api/search?q=<script>"

# Admin access  -> 200
curl http://localhost:8081/admin/

⚠️ What these rules do NOT catch

Stated plainly, because a test that looks like it passed is worse than a known gap. These return 200 on this node:

# SQL injection with no keyword the rule looks for  -> 200 (NOT blocked)
# The rule matches "union select", "drop table" and "insert into" only, so a
# very common form of injection passes straight through.
curl "http://localhost:8081/api/search?q=or+1=1--"

# URL-encoded metacharacters defeat the pattern match  -> 200 (NOT blocked)
# %3C is "<", so the rule's "<script" never matches the raw query string.
curl "http://localhost:8081/api/search?q=%3Cscript%3E"

Sending a raw < or a space inside a quoted URL can also be rejected by curl before the request leaves the machine. If you see curl: (3) URL rejected, nothing was tested — the request never arrived.

This server is monitored by the nginx WAF AI system for threat detection and automatic rule generation.
