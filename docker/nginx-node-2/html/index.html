🛡️ Nginx Node 2 - WAF AI Demo

ℹ️ Server Information

  • Node ID: nginx-node-2
  • Purpose: E-commerce demo server for WAF AI testing
  • Port: 8082 (external)
  • WAF Status: Protected

🛒 Available API Endpoints

  • GET /api/products - Product catalog
  • GET /api/orders - Order management
  • GET /api/cart - Shopping cart
  • GET /dashboard/ - Admin dashboard (restricted)

🔒 Security Features

  • Rate Limiting: 10 requests/second (general), 5 requests/second (API)
  • WAF Rules: AI-generated rules applied dynamically
  • Security Headers: XSS protection, content type options, frame options
  • Dashboard Protection: Enhanced security for /dashboard/ paths
  • File Blocking: Sensitive files (.env, .git, etc.) blocked

🧪 Testing Commands

Test this server with various requests. Every command below was run against this node and the status shown is what it actually returns.

# Normal request  -> 200
curl http://localhost:8082/

# API request  -> 200
curl http://localhost:8082/api/products

# SQL injection attempt  -> 403 (blocked)
# The payload must be URL-safe: spaces as + , and it is quoted, so the shell
# does not eat the quote character. An unencoded space makes curl refuse the URL
# outright (curl: (3) URL rejected) and NOTHING reaches the WAF at all.
curl "http://localhost:8082/api/orders?id=1+UNION+SELECT+*+FROM+users--"

# XSS attempt  -> 403 (blocked)
curl "http://localhost:8082/api/cart?item=<img+src=x+onerror=alert(1)>"

# Admin dashboard  -> 200
curl http://localhost:8082/dashboard/

⚠️ What these rules do NOT catch

Stated plainly, because a test that looks like it passed is worse than a known gap. These return 200 on this node:

# SQL injection without a keyword the rule looks for  -> 200 (NOT blocked)
curl "http://localhost:8082/api/orders?id=1+OR+1=1--"

# URL-encoded metacharacters defeat the pattern match  -> 200 (NOT blocked)
# %3D is "=", so the rule's "onerror=" never matches the raw query string.
curl "http://localhost:8082/api/cart?item=%3Cimg+src%3Dx+onerror%3Dalert(1)%3E"

Sending a raw < or a space inside a quoted URL can also be rejected by curl before the request leaves the machine. If you see curl: (3) URL rejected, nothing was tested — the request never arrived.

This e-commerce server is monitored by the nginx WAF AI system for threat detection and automatic rule generation.
